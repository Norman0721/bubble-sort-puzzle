# 游戏流程检查与修复记录 · V1.2

本次按照用户要求检查“莫名失败”和不合理操作。检查执行单文件中实际的 Game/LevelSelect Scene、轨迹、消除与计分代码，用模拟的 Phaser 绘图/音频接口、时钟和输入事件运行。没有使用真实浏览器渲染，也没有把模拟测试当作触屏实机或帧率验收。

## 已确认并修复

| 问题 | 复现与影响 | 修复 |
| --- | --- | --- |
| 同一发弹药重复结算 | 构造结算回调迟到，超时保护先结算；旧回调再到达。红/蓝各一发、红/蓝各4球的场景中，旧版只发射一发，ammo.pos却变成2，蓝球仍在就判失败。这是可模拟复现的提前失败路径，不代表已经证明真实设备一定会触发该调度顺序。 | 每发有独立序号，回调绑定发射序号和本局ID；结算只允许一次，旧回调不能结算新的弹药。 |
| 鼠标按下即发射且方向过时 | 点击左上球时，未先更新角度，仍按先前竖直角度发射；也无法按承诺的拖动/松手发射。 | 鼠标和触摸统一为按下开始、拖动瞄准、松开发射一次，最终方向来自释放位置。菜单留白和右键不耗弹，区域外释放取消。 |
| 仅悬停底部就改变炮台位置 | 没有按住鼠标，经过底部区域也会走位；底部拖动跨进棋盘还可能改变手势语义。 | 只在按住的底部走位手势中移动，手势类型在开始时确定，走位松手不会发射。 |
| 窄关卡炮台越界 | 24列关卡炮台在x=620，转18列关卡后仍保持x=620，但该关合法范围约126.25…545.75；轨迹会从墙外开始，落点可能跑到炮台下方。 | 开局恢复中央位置和向上角度，清空残留触摸状态；所有走位夹在当前轨道内。 |
| 失败后撤销仍受遮罩拦截 | 撤销恢复了棋盘，却保留全屏结算矩形，点击仍触发重开；结算撤销的点击也能冒泡到游戏发射处理器。 | 完整销毁结算UI、阻止结算操作冒泡；第一发失败也能撤销。文字改为“撤销最后一发”，不再承诺退回与实际不符的发射序号。 |
| 多指与取消手势误发射 | A指开始瞄准，B指松开就会替A指发射；失焦/系统取消后也可能留住瞄准状态。 | 追踪发起手指的ID，只接受该指释放；窗口失焦、pointercancel、touchcancel、区域外释放均清理手势。 |
| 浅角反弹提前消失 | 6列地图从x=295、-173°发射，本应经过45段轨迹击中顶部红球；旧版在第7段、y≈898.51处就终止，判未命中。 | 提高有界反弹计算上限至128，覆盖最窄合法棋盘和最小合法仰角；预览与实际发射使用同一算法。 |
| 长按空格继续耗弹 | 键盘重复keydown可能在上一发结算结束后立即发射下一发。 | 发射快捷键忽略自动重复事件，只响应新的按键动作。 |
| 撤销统计不完整 | 棋盘、用弹数恢复，但连击/最高连击、炮台和瞄准方向没有恢复。 | 快照包含这些字段，并在撤销时恢复；禁用不可用的撤销按钮，禁止飞行中撤销，保留每局最多3次限制。 |
| 反弹光圈位置错位 | 走位后炮口反弹光圈/徽标停在旧位置；发射后弹体光圈停在出发点。 | 光圈和徽标跟随炮台；飞行光圈跟随弹体位置。 |
| 触屏选关与滚动冲突 | 卡片pointerdown立即选关，手指还没上下滑动就加载游戏。 | 触摸松手确认，移动超过8逻辑像素视为滑动；取消事件清理待确认卡片。 |
| 结算连点重复切换 | 多次点击结算背景可以多次排队重开/下一关。 | 首次确认后锁定结算动作，恢复撤销时解锁。 |
| 异常关卡入口报错 | 负数/小数索引、损坏的试玩JSON可进入不可用关卡，随后访问undefined数据。 | 限制索引；损坏试玩回退到正常关卡，无关卡则返回首页。 |

## 检查结果

`node --test tests/*.test.js`：61项通过，其中新增14项游戏行为测试。涵盖迟到回调、误发射、失败撤销、触屏取消、反弹、统计恢复、20次重开监听清理，以及全部50关首发预览与实际消除/计数一致性。原有首页、关卡编辑器和试玩返回测试均通过。开发版和不含编辑器的玩家版均通过脚本语法与启动检查。

`node game/audit.js`：实际游戏逻辑的50关自动流程扫描，运行异常0，未发现用弹计数与实际发射次数不同或提前判失败。使用有限的贪心自动玩家，25关通关；另25关走到正常弹药耗尽。后25关不等于无解，也不能据此宣称它们已通过通关验证。完整关卡可解性、最佳/完美路线仍需要更强搜索或真实通关检查。结果保存在 `audit-results.json`。

剩余限制：尚未验证真实浏览器的渲染、触控、音频上下文、操作系统中断、帧率和实机内存。此次对迟到回调的测试是故障注入，主要用于证明保护代码不会错误耗弹。未调整内置关卡布局、弹药顺序、颜色和容量。

源码修复位于 `game/repairs.js`，打包器保留原始引擎基线并应用修复；反弹预算与旧提示/文案处理在 `editor/build.py`。桌面最终交付仍为单文件 `Bubble Sort Staggered.html`，版本1.2。
